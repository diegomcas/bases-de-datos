Introducción

Las organizaciones modernas dependen cada vez más de la gestión eficiente de la información. Empresas, hospitales, universidades y organismos públicos almacenan grandes volúmenes de datos para apoyar sus operaciones y la toma de decisiones.

Sin embargo, la forma en que los datos se almacenan y administran ha evolucionado significativamente a lo largo del tiempo.

Antes de la aparición de los Sistemas de Gestión de Bases de Datos (SGBD), las aplicaciones informáticas utilizaban métodos mucho más simples para manejar información, basados principalmente en archivos independientes.

Comprender esta evolución permite entender:

  • por qué surgieron los SGBD
  • qué problemas intentan resolver
  • cómo se organiza internamente una base de datos moderna

Sistemas basados en archivos

Antes de la década de 1970, muchas aplicaciones se desarrollaban utilizando sistemas de archivos independientes.

En este modelo:

  • cada programa administra sus propios datos
  • cada archivo tiene un formato particular
  • no existe un sistema centralizado de gestión de datos

Cada programa conoce únicamente sus propios archivos. Esto genera múltiples dificultades cuando el sistema crece.

Ejemplo de “Arquitectura basada en archivos”:

  • Programa Turnos → archivo: turnos.txt
  • Programa Facturación → archivo: facturas.dat
  • Programa Farmacia → archivo: farmacia.csv
  • Programa Laboratorio → archivo: laboratorio.dat

Problemas de los sistemas basados en archivos

A medida que las organizaciones almacenan más información, los sistemas basados en archivos comienzan a mostrar limitaciones importantes.

Los problemas principales son:

  • redundancia de datos
  • inconsistencia de datos
  • dificultad de acceso
  • aislamiento de la información

Redundancia de datos

La redundancia ocurre cuando la misma información se almacena varias veces en distintos archivos.

Ejemplo:

Archivo Turnos → Juan Pérez

Archivo Facturación → Juan Pérez

Archivo Farmacia → Juan Pérez

Archivo Laboratorio → Juan Pérez

Consecuencias:

  • mayor uso de almacenamiento
  • mayor costo de mantenimiento
  • mayor probabilidad de errores

Inconsistencia de datos

La inconsistencia ocurre cuando distintas copias del mismo dato contienen valores diferentes.

  • Ejemplo

Sistema Turnos →Tel: 351-444-555

Sistema Emergencias →Tel: 351-333-111

Esto genera pérdida de confiabilidad en la información.

Dificultad de acceso a la información

En los sistemas de archivos, obtener información específica requiere programar soluciones a medida.

Ejemplo de consulta:

¿Cuántos pacientes mayores de 60 años fueron atendidos en invierno?

Sin un sistema de base de datos, esta consulta puede requerir programación adicional.

Aislamiento de los datos

Los datos están distribuidos en múltiples archivos con distintos formatos.

Esto dificulta combinar información.

Ejemplo:

  • archivo farmacia
  • archivo historia clínica

Relacionarlos puede ser técnicamente complejo.

Sistemas de Gestión de Bases de Datos (SGBD)

¿Qué es una Base de Datos?

Una base de datos es un conjunto organizado de datos relacionados entre sí, que se almacenan de manera estructurada para permitir su consulta, actualización y gestión de forma eficiente.

El objetivo principal de una base de datos es representar información sobre algún aspecto del mundo real, de manera que pueda ser utilizada por personas o sistemas informáticos para realizar distintas actividades, como registrar información, analizarla o tomar decisiones.

En una organización, las bases de datos permiten almacenar información sobre distintos elementos de su actividad cotidiana, por ejemplo:

  • clientes
  • productos
  • empleados
  • ventas
  • proveedores
  • operaciones administrativas

A diferencia de una simple colección de archivos o documentos aislados, una base de datos presenta algunas características fundamentales:

Organización estructurada

Los datos se organizan siguiendo un modelo que define cómo se relacionan entre sí.

Relación entre los datos

Los distintos conjuntos de información no se encuentran aislados, sino vinculados entre sí de forma lógica.

Persistencia

La información se almacena de forma permanente para poder ser utilizada en distintos momentos.

Acceso y actualización

Los datos pueden ser consultados, modificados o ampliados cuando sea necesario.

Sin embargo, a medida que la cantidad de datos crece y aumenta el número de usuarios que necesitan acceder a ellos, administrar esta información manualmente o mediante archivos simples se vuelve complejo. Surgen entonces problemas como:

  • duplicación de datos
  • inconsistencias en la información
  • dificultades para acceder a los datos
  • falta de control de seguridad
  • conflictos cuando varios usuarios intentan usar la información al mismo tiempo

Para resolver estos problemas se utilizan los Sistemas de Gestión de Bases de Datos, que proporcionan herramientas especializadas para administrar grandes volúmenes de información de forma segura y eficiente.

¿Qué es un Sistema de Gestión de Bases de Datos?

Un Sistema de Gestión de Bases de Datos (SGBD) es un software especializado diseñado para almacenar, organizar, proteger y administrar grandes volúmenes de datos estructurados.

El SGBD actúa como intermediario entre:

  • las aplicaciones
  • los usuarios
  • los datos almacenados

De esta manera, las aplicaciones no interactúan directamente con los archivos físicos, sino que solicitan información al SGBD, que se encarga de localizarla, validarla y entregarla.

En resumen, la arquitectura de los datos con SGBD se puede graficar de la siguiente manera:

Aplicaciones
↓
SGBD
↓
Base de Datos

El SGBD centraliza la gestión de los datos y proporciona múltiples servicios que permiten que el sistema sea confiable, seguro y eficiente.

Funciones principales de un SGBD

Un SGBD proporciona múltiples servicios fundamentales:

  • almacenamiento estructurado de información
  • acceso eficiente a grandes volúmenes de datos
  • control de acceso a la información
  • gestión de múltiples usuarios simultáneos
  • recuperación ante fallos
  • mantenimiento de la integridad de los datos

Estas capacidades representan ventajas competitivas clave frente a los sistemas basados en archivos.

Ventajas competitivas de los SGBD

Los sistemas de gestión de bases de datos ofrecen ventajas fundamentales que permiten que las organizaciones manejen información crítica de manera confiable.

Entre las más importantes se encuentran:

  • integridad de los datos
  • seguridad de la información
  • concurrencia de acceso

Integridad de los datos

La integridad de los datos se refiere a la capacidad del sistema para garantizar que la información almacenada sea correcta, coherente y válida.

Los SGBD permiten definir reglas y restricciones que los datos deben cumplir.

Ejemplos de reglas de integridad:

  • un paciente no puede tener un número de identificación duplicado
  • un turno no puede asignarse a un médico inexistente
  • una factura debe estar asociada a un cliente válido

Si un usuario intenta introducir datos que violen estas reglas, el SGBD rechaza la operación, evitando que la base de datos quede en un estado inconsistente.

Ejemplo:

Intento de registrar turno → ID_MEDICO = 145

Si el médico no existe → operación rechazada

Esto garantiza que la información almacenada mantenga su coherencia lógica.

Seguridad de la información

La seguridad es la capacidad del sistema para controlar quién puede acceder a los datos y qué acciones puede realizar sobre ellos.

Los SGBD permiten definir niveles de acceso diferenciados para distintos tipos de usuarios.

Por ejemplo:

Usuario Permisos
Recepcionista ver turnos
Farmacéutico ver medicamentos
Contador ver facturación
Administrador acceso completo

Esto evita que usuarios no autorizados puedan:

  • acceder a información sensible
  • modificar datos críticos
  • eliminar información importante

Además, muchos SGBD incluyen mecanismos adicionales como:

  • autenticación de usuarios
  • registro de actividades (logs)
  • cifrado de datos

Estos mecanismos son fundamentales en sistemas que manejan información sensible, como historias clínicas o datos financieros.

Concurrencia de acceso

En sistemas reales, múltiples usuarios pueden necesitar acceder simultáneamente a la base de datos.

Por ejemplo:

  • dos secretarias registrando turnos
  • un médico consultando una historia clínica
  • el sistema de facturación generando un comprobante

El SGBD gestiona este acceso simultáneo mediante mecanismos de control de concurrencia.

El objetivo es evitar situaciones como:

  • pérdida de información
  • modificaciones conflictivas
  • resultados incorrectos

Ejemplo:

Dos usuarios intentan reservar el mismo turno médico al mismo tiempo.

Usuario A → solicita turno 10:00

Usuario B → solicita turno 10:00

El SGBD actúa como árbitro, permitiendo que solo una operación se complete y evitando que el turno quede duplicado.

Este control garantiza que la base de datos mantenga consistencia incluso bajo alta carga de trabajo.

Cuadro comparativo: Ventajas clave de los SGBD

Característica Sistemas de Archivos Sistemas con SGBD
Integridad de datos Difícil de garantizar Reglas automáticas
Seguridad Limitada Control de acceso
Concurrencia Riesgo de conflictos Gestión automática
Consistencia Vulnerable a errores Controlada por el sistema

Transacciones en los sistemas de bases de datos

En un sistema de base de datos, muchas operaciones sobre los datos no ocurren de manera aislada.

Frecuentemente, una acción del usuario implica varios pasos que deben ejecutarse como una única operación lógica.

Por ejemplo, cuando un paciente paga una consulta médica, el sistema puede necesitar:

  • registrar el pago en la cuenta del paciente
  • actualizar el saldo de la clínica
  • registrar la operación en el historial de facturación

Aunque estas acciones son técnicamente varias operaciones sobre la base de datos, desde el punto de vista del sistema constituyen una sola unidad de trabajo.

A este conjunto de operaciones se lo denomina transacción.

Definición:

Una transacción es una secuencia de operaciones sobre la base de datos que se ejecutan como una unidad lógica indivisible.

Esto significa que todas las operaciones de la transacción deben ejecutarse correctamente para que el resultado sea válido.

El problema de la confiabilidad

En sistemas reales pueden ocurrir múltiples situaciones que afecten la ejecución de una transacción:

  • fallos del sistema
  • cortes de energía
  • errores de software
  • acceso simultáneo de múltiples usuarios

Si estos eventos ocurren en medio de una operación compleja, la base de datos podría quedar en un estado inconsistente.

Por ejemplo:

  • se registra un pago, pero el sistema falla antes de actualizar el saldo.

El resultado sería una base de datos incorrecta.

Para evitar este tipo de problemas, los sistemas de gestión de bases de datos implementan un conjunto de garantías conocidas como propiedades ACID.

El modelo ACID

Las propiedades ACID definen los principios que deben cumplir las transacciones para garantizar que la base de datos permanezca correcta, confiable y consistente, incluso ante fallos o acceso simultáneo.

El término ACID es un acrónimo formado por las iniciales de cuatro propiedades fundamentales:

Propiedad Significado
A Atomicidad
C Consistencia
I Aislamiento (Isolation)
D Durabilidad

Estas propiedades actúan como garantías que el SGBD ofrece a las aplicaciones y a los usuarios.

Si una transacción cumple estas cuatro propiedades, el sistema puede asegurar que los datos permanecerán correctos y confiables.

Atomicidad

La atomicidad establece que una transacción debe ejecutarse completamente o no ejecutarse en absoluto.

Si ocurre un error durante su ejecución, el sistema deshace todos los cambios realizados hasta ese momento.

Esto se conoce como el principio de “todo o nada”.

Ejemplo:

  1. Registrar pago
  2. Actualizar saldo
  3. Registrar operación

Si falla el paso 3 → el sistema deshace los pasos 1 y 2

De esta manera se evita que la base de datos quede en un estado incompleto.

Consistencia

La consistencia garantiza que la base de datos siempre pase de un estado válido a otro estado válido.

Esto significa que todas las reglas definidas para los datos deben respetarse antes y después de cada transacción.

Ejemplos de reglas de consistencia:

  • un saldo no puede ser negativo
  • un turno debe corresponder a un médico existente
  • una factura debe estar asociada a un cliente válido

Si una operación viola alguna de estas reglas, el sistema rechaza la transacción.

Aislamiento

El aislamiento se refiere a la capacidad del sistema para manejar múltiples transacciones que se ejecutan simultáneamente sin que interfieran entre sí.

En entornos reales, muchos usuarios pueden acceder a la base de datos al mismo tiempo.

Por ejemplo:

  • una secretaria registra turnos
  • un médico consulta historias clínicas
  • el sistema de facturación genera comprobantes

El SGBD debe asegurar que estas operaciones no produzcan resultados incorrectos.

Desde el punto de vista de cada transacción, el sistema debe comportarse como si fuera la única que se está ejecutando.

Durabilidad

La durabilidad garantiza que, una vez que una transacción ha sido confirmada exitosamente, los cambios realizados en la base de datos permanecerán almacenados incluso si ocurre un fallo del sistema.

Para lograr esto, los SGBD utilizan mecanismos como:

  • registros de transacciones (logs)
  • almacenamiento persistente
  • técnicas de recuperación ante fallos

De esta forma, si el sistema se reinicia después de una falla, los cambios confirmados no se perderán.

Síntesis de las propiedades ACID

Propiedad Garantía
Atomicidad la transacción se ejecuta completa o se cancela
Consistencia la base de datos permanece en un estado válido
Aislamiento las transacciones concurrentes no interfieren
Durabilidad los cambios confirmados no se pierden

Importancia de ACID

Las propiedades ACID son fundamentales para garantizar que los sistemas de bases de datos puedan manejar información crítica de manera confiable.

Gracias a estas garantías, es posible utilizar bases de datos en sistemas donde la precisión de los datos es esencial, como:

  • sistemas financieros
  • sistemas hospitalarios
  • sistemas de reservas
  • plataformas de comercio electrónico

En estos contextos, incluso un pequeño error en los datos puede tener consecuencias importantes.

Arquitectura ANSI/SPARC

¿Qué se entiende por Arquitectura de Datos?

La arquitectura de datos es la disciplina que define cómo se organizan, estructuran, almacenan, integran y utilizan los datos dentro de un sistema o una organización. Su objetivo principal es establecer un marco ordenado que permita que los datos sean comprensibles, confiables, accesibles y útiles para quienes los necesitan.

En términos simples, la arquitectura de datos responde a preguntas como:

  • ¿Qué datos existen en un sistema?
  • ¿Cómo están organizados?
  • ¿Dónde se almacenan?
  • ¿Cómo se relacionan entre sí?
  • ¿Quién puede acceder a ellos y de qué manera?

Desde una perspectiva conceptual, la arquitectura de datos busca representar el mundo real mediante estructuras de información, de modo que los sistemas informáticos puedan registrar, procesar y recuperar información de forma eficiente.

Dentro de un sistema informático, la arquitectura de datos cumple varias funciones fundamentales:

  • Organización: establece una estructura clara para los datos.
  • Consistencia: asegura que la información mantenga coherencia en todo el sistema.
  • Integración: permite que distintos sistemas compartan y utilicen los mismos datos.
  • Escalabilidad: facilita que el sistema pueda crecer sin perder orden ni eficiencia.
  • Gobernanza: define reglas sobre cómo se crean, modifican y utilizan los datos.

Por esta razón, la arquitectura de datos es un componente central en el diseño de sistemas de información, ya que los procesos informáticos dependen directamente de la calidad y organización de los datos.

En el ámbito de las bases de datos, la arquitectura de datos se materializa en diferentes niveles de representación, como los propuestos por la arquitectura ANSI/SPARC, que separa la forma en que los datos se conciben, se organizan lógicamente y se almacenan físicamente.

En síntesis, puede decirse que la arquitectura de datos constituye el plano estructural de la información de un sistema, del mismo modo que los planos de arquitectura organizan los espacios y elementos de un edificio.

La necesidad de niveles de abstracción

A medida que los sistemas informáticos comenzaron a manejar volúmenes cada vez mayores de información, surgió un problema fundamental: los datos podían ser utilizados por muchos usuarios y aplicaciones diferentes, cada uno con necesidades distintas.

Por ejemplo, en el sistema de información de una clínica médica:

  • una secretaria necesita ver los turnos asignados a los médicos
  • un médico necesita consultar la historia clínica de sus pacientes
  • el departamento administrativo necesita acceder a la facturación
  • la dirección requiere estadísticas generales sobre la actividad del centro médico

Aunque todos utilizan el mismo sistema, no todos necesitan ver la misma información ni interactuar con los datos de la misma manera.

Al mismo tiempo, el sistema debe gestionar aspectos técnicos como:

  • cómo se almacenan los datos en disco
  • cómo se organizan los archivos
  • qué estructuras permiten acelerar las búsquedas

Si todos estos aspectos estuvieran mezclados en un único nivel, cualquier cambio técnico podría afectar a todas las aplicaciones que utilizan la base de datos.

Por ejemplo:

  • cambiar la forma en que se almacenan los archivos
  • modificar la estructura de almacenamiento
  • agregar nuevos datos al sistema

Estos cambios podrían obligar a reescribir gran parte del software, lo cual generaría altos costos de mantenimiento y gran complejidad.

Para resolver este problema, los sistemas de bases de datos introducen el concepto de niveles de abstracción.

Concepto de abstracción en bases de datos

La abstracción consiste en ocultar los detalles técnicos innecesarios para cada tipo de usuario, mostrando únicamente la información relevante para su tarea.

En el contexto de los sistemas de bases de datos, esto significa separar:

  • la forma en que los datos se almacenan físicamente
  • la estructura lógica de la información
  • la forma en que los usuarios acceden a los datos

Esta separación permite que los cambios en un nivel no afecten necesariamente a los otros niveles.

El modelo ANSI/SPARC

Para formalizar esta idea, el comité ANSI/SPARC (American National Standards Institute / Standards Planning and Requirements Committee) propuso en la década de 1970 una arquitectura conceptual para los sistemas de bases de datos.

Este modelo introduce una estructura de tres niveles de abstracción, que separa claramente:

  • la representación física de los datos
  • la organización lógica de la información
  • las vistas específicas utilizadas por los usuarios

El objetivo principal de esta arquitectura es facilitar la independencia de los datos, permitiendo que los sistemas evolucionen sin afectar a las aplicaciones existentes.

Arquitectura de tres niveles

La arquitectura se presenta en tres niveles:

  1. Nivel Externo (vistas de usuario)
  2. Nivel Conceptual (modelo lógico)
  3. Nivel Interno (almacenamiento físico)

Nivel Externo

Representa la visión que cada usuario tiene de la base de datos.

Ejemplo:

Usuario Información visible
Secretaria turnos
Farmacéutico recetas
Director estadísticas

Nivel Conceptual

Representa la estructura lógica global de la base de datos.

Define:

  • qué datos existen
  • cómo se relacionan
  • qué reglas se aplican

Este nivel es el que se diseña mediante modelado de datos.

Nivel Interno

Describe cómo se almacenan físicamente los datos.

Incluye:

  • archivos
  • índices
  • estructuras de almacenamiento

Este nivel busca optimizar el rendimiento del sistema.

Independencia de datos

Uno de los objetivos de la arquitectura ANSI/SPARC es lograr independencia de datos.

Esto significa que ciertos cambios pueden realizarse sin afectar a las aplicaciones existentes.

Tipos de independencia

Tipo Descripción
Independencia física La operación se ejecuta completamente o no se ejecuta
Independencia lógica Cambios en almacenamiento sin modificar estructura lógica

Diccionario de datos

El diccionario de datos es un componente interno del SGBD que almacena información sobre la estructura de la base de datos.

Contiene información sobre:

  • tablas
  • tipos de datos
  • relaciones
  • restricciones
  • permisos

En otras palabras, almacena metadatos, es decir, datos sobre los datos.

Conclusión

Los Sistemas de Gestión de Bases de Datos constituyen una tecnología fundamental para la organización y administración de información en sistemas informáticos modernos.

Al proporcionar mecanismos para:

  • estructurar datos
  • controlar su acceso
  • mantener su integridad
  • garantizar su disponibilidad

los SGBD permiten gestionar información de forma confiable y eficiente.

Estos conceptos constituyen la base necesaria para abordar el modelado de datos, tema central en el diseño de bases de datos.
