01

Vistas (Views) - Soluciones

Facilitar el acceso a datos agrupados sin escribir JOINs

Consejo de trabajo

Fijate que la vista te deja traer datos de 7 tablas distintas sin haber estudiado todavía la teoría de los JOIN. Esa es la razón por la que las vistas se usan tanto: encapsulan una consulta compleja detrás de un nombre, y quien la consulta después no necesita saber cómo está armada.

  • Reto 1.1

    Ver el contenido de la vista existente

    Volver a la consigna
    SQL 
    SELECT * FROM orden_servicio_completa;

    Explicación: Aunque por debajo hace una query con 7 JOINs y un GROUP_CONCAT para agrupar los problemas y equipos, solo necesitás tratarla como si fuera una tabla común y corriente.

  • Reto 1.2

    Buscar órdenes del cliente García

    Volver a la consigna
    SQL 
    SELECT `Nro Orden`, `Estado Actual`, `Modelos` 
FROM orden_servicio_completa 
WHERE Cliente LIKE '%García%';

    Explicación: En la vista, la columna Cliente concatena apellido y nombre, por lo que usar LIKE '%García%' es el camino más robusto. Muestra cómo esto devuelve solo los campos necesarios de forma simple.

  • Reto 1.3

    Comprobar la actualización dinámica de datos (Paso a Paso)

    Volver a la consigna

    Instrucciones y código que deben ejecutar en consola secuencialmente:

    SQL - Secuencia 
    -- 1. Buscamos a la cliente (da vacío)
SELECT * FROM orden_servicio_completa WHERE Cliente LIKE '%Fernández%';

-- 2. Insertamos en cliente (Laura Fernández pasa a ser la ID 6)
INSERT INTO cliente (nombre, apellido) VALUES ('Laura', 'Fernández');

-- 3. Si volvemos a consultar la vista, sigue vacía porque Laura no tiene órdenes asociadas.
SELECT * FROM orden_servicio_completa WHERE Cliente LIKE '%Fernández%';

-- 4. Registramos su orden de servicio
INSERT INTO orden_servicio (fecha_ingreso, id_empleado, id_cliente, id_orden_estado, total) 
VALUES (NOW(), 2, 6, 1, 0.00);

-- 5. Le asociamos su equipo (Samsung Galaxy S21 = ID 1) y su problema (Pantalla rota = ID 1)
INSERT INTO orden_servicio_has_equipo (nro_orden, id_equipo, id_problema) 
VALUES (4, 1, 1);

-- 6. Consultamos la vista final. ¡Ahora sí aparece la orden número 4 cruzando todos los datos!
SELECT * FROM orden_servicio_completa WHERE Cliente LIKE '%Fernández%';
  • Reto 1.4

    Crear la vista de catálogo seguro (Sin stock)

    Volver a la consigna
    SQL 
    CREATE VIEW vista_catalogo_repuestos AS
SELECT nombre, precio_unitario 
FROM repuesto;

-- Comprobación:
SELECT * FROM vista_catalogo_repuestos;

    Explicación: Este ejercicio les permite usar CREATE VIEW por primera vez con sintaxis básica (SELECT simple). Es excelente para introducir el concepto de seguridad a nivel de columnas: el usuario final solo ve lo que la vista expone y no puede acceder al inventario físico.

02

Índices (Indexes) - Soluciones

Optimizar el rendimiento en consultas frecuentes

Consejo de trabajo

La base de prueba tiene apenas 6 filas y responde en 0.00 segundos, así que el tiempo no te va a decir nada sobre si el índice sirve. Usá EXPLAIN y mirá la columna rows: ese es el contador de esfuerzo del motor, y es donde se ve la diferencia.

  • Reto 2.1

    Explicar la consulta antes de tener el índice

    Volver a la consigna
    SQL 
    EXPLAIN SELECT * FROM cliente WHERE apellido = 'García';

    Salida esperada de MySQL:
    La columna type mostrará ALL (Full Table Scan). La columna rows mostrará el total de registros de la tabla (5 o 6). Esto comprueba que MySQL tuvo que leer todo el disco físico para encontrar una coincidencia.

  • Reto 2.2

    Creación del índice de apellido

    Volver a la consigna
    SQL 
    CREATE INDEX idx_cliente_apellido ON cliente(apellido);
  • Reto 2.3

    Explicar la consulta después de aplicar el índice

    Volver a la consigna
    SQL 
    EXPLAIN SELECT * FROM cliente WHERE apellido = 'García';

    Salida esperada de MySQL:
    La columna type cambia a ref. La columna key mostrará que usó idx_cliente_apellido. La columna rows dirá 1. Esto demuestra que MySQL fue directo a la dirección física del registro sin leer nada más.

03

Procedimientos Almacenados - Soluciones

Creación y llamado seguro de bloques de código en MySQL

Consejo de trabajo

Fijate que los parámetros llevan el prefijo p_ —por ejemplo p_id_repuesto— para no confundirse con los nombres de las columnas. Si el parámetro se llamara igual que la columna, la sentencia quedaría WHERE id_repuesto = id_repuesto, que es siempre verdadero y actualizaría la tabla entera. Es justo lo que Martín quería evitar.

  • Reto 3.1

    Crear procedimiento de actualización

    Volver a la consigna
    SQL 
    DELIMITER //
CREATE PROCEDURE cambiar_precio_repuesto(
    IN p_id_repuesto INT, 
    IN p_nuevo_precio DECIMAL(10,2)
)
BEGIN
    UPDATE repuesto 
    SET precio_unitario = p_nuevo_precio 
    WHERE id_repuesto = p_id_repuesto;
END //
DELIMITER ;

    Explicación: Usa el delimitador // para que MySQL no corte la compilación al encontrar el punto y coma interno del UPDATE. Los parámetros IN indican datos de entrada.

  • Reto 3.2

    Verificar y llamar al procedimiento

    Volver a la consigna
    SQL 
    -- Consulta previa para ver precio actual (45000.00)
SELECT nombre, precio_unitario FROM repuesto WHERE id_repuesto = 1;

-- Llamamos al SP
CALL cambiar_precio_repuesto(1, 48000.00);

-- Verificamos el cambio
SELECT nombre, precio_unitario FROM repuesto WHERE id_repuesto = 1;
04

Triggers (Disparadores) - Soluciones

Validar la integridad de los datos en tiempo real de forma automática

Consejo de trabajo

NEW representa el registro modificado tal como quiere entrar a la base. Usar BEFORE UPDATE te permite frenarlo en la puerta, antes de que reemplace al registro viejo. SIGNAL es la interrupción que cancela la transacción y devuelve el error.

  • Reto 4.1

    Crear el disparador de stock mínimo

    Volver a la consigna
    SQL 
    DELIMITER //
CREATE TRIGGER trg_control_stock_negativo
BEFORE UPDATE ON repuesto
FOR EACH ROW
BEGIN
    IF NEW.stock < 0 THEN
        SIGNAL SQLSTATE '45000' 
        SET MESSAGE_TEXT = '¡Error! No se puede tener stock negativo en El Chip.';
    END IF;
END //
DELIMITER ;
  • Reto 4.2

    Intentar romper el trigger y verificar

    Volver a la consigna
    SQL 
    -- Lanzar la actualización inválida
UPDATE repuesto SET stock = -5 WHERE id_repuesto = 1;
-- Mensaje arrojado: Error Code: 1644. ¡Error! No se puede tener stock negativo en El Chip.

-- Comprobar que el valor no cambió (sigue siendo el stock original)
SELECT stock FROM repuesto WHERE id_repuesto = 1;
