Antes de empezar: tips de supervivencia

Esta práctica se resuelve desde el MySQL Command Line Client, escribiendo las sentencias a mano. No hay asistentes ni grillas que nos salven: lo que escribimos es lo que se ejecuta. Por eso, tres reglas antes de tocar el teclado:

  1. 1. Terminá siempre con ; Sin el punto y coma el cliente asume que la sentencia sigue y se queda esperando con el prompt ->. Si eso pasa, escribí ; y presioná Enter (o cancelá con \c).
  2. 2. Verificá el WHERE antes de ejecutar un UPDATE o un DELETE. Un DELETE sin WHERE borra la tabla entera y no hay Ctrl+Z. La costumbre profesional es escribir primero el SELECT con ese mismo WHERE, mirar qué filas devuelve, y recién entonces cambiar el verbo.
  3. 3. Explorá antes de operar. SELECT * FROM tabla LIMIT 10; te muestra los primeros registros y te dice qué columnas tiene realmente la tabla. DESCRIBE tabla; te muestra la estructura sin traer datos.
Analogía cotidiana: el WHERE es la puntería. El UPDATE y el DELETE son el disparo. Nadie dispara primero y apunta después.

Necesito saber qué repuestos están por agotarse, encontrar a un cliente por el apellido, ver cuáles son las reparaciones más caras de mano de obra y qué tipos de equipo manejamos. Y algo importante: quiero saber qué órdenes todavía no le entregué al cliente, porque tengo el mostrador lleno de aparatos."

Sustento Teórico: la consulta básica

  • Estructura mínima: SELECT columnas FROM tabla WHERE condición ORDER BY columna;
  • SELECT elige qué columnas se muestran (proyección). * significa "todas".
  • WHERE elige qué filas se muestran (selección). Operadores: =, <>, >, <, >=, <=, BETWEEN ... AND ..., IN (...), LIKE, IS NULL.
  • ORDER BY ordena el resultado final: ASC (ascendente, es el valor por defecto) o DESC (descendente).
  • DISTINCT elimina las filas repetidas del resultado.
  • Un detalle clave: se puede ordenar por una columna que no está en el SELECT. El motor la usa para ordenar aunque no la muestre.
Analogía cotidiana: el FROM es el fichero del que sacamos las carpetas, el WHERE es el criterio con el que descartamos carpetas sin abrirlas, el SELECT es qué hojas fotocopiamos de cada carpeta que sobrevivió, y el ORDER BY es el orden en que apilamos las fotocopias sobre el escritorio.
⚠️ El valor NULL no es un valor: NULL significa "no se sabe". Por eso columna = NULL nunca da verdadero (ni siquiera cuando la columna es nula): hay que escribir columna IS NULL o columna IS NOT NULL. Esto va a ser decisivo en el Reto 1.6.

Inserción de Datos (INSERT)

El negocio crece y llegan cosas nuevas

M

Martín dice:

"Llegó mercadería nueva y también un cliente que quiero cargar ya mismo. Necesito dar de alta un módulo de pantalla para Samsung A54, sumar una marca que antes no trabajábamos, y abrir una orden de servicio nueva a nombre de Carlos López, que la trajo hoy y todavía no la miramos."

Sustento Teórico: la sentencia INSERT

  • Forma recomendada: INSERT INTO tabla (col1, col2) VALUES (val1, val2); Nombrar las columnas explícitamente es lo que hace que la sentencia siga funcionando aunque mañana alguien agregue una columna a la tabla.
  • Columnas que NO se escriben: las AUTO_INCREMENT (como id_repuesto) las genera el motor sola; las que tienen DEFAULT toman su valor si las omitimos.
  • Columnas que SÍ o SÍ hay que escribir: las declaradas NOT NULL sin valor por defecto. Si falta una, MySQL rechaza la fila.
  • Claves foráneas: para insertar una fila que apunta a otra tabla (una orden apunta a un cliente, a un empleado y a un estado) hay que conocer los IDs de esas tablas. Si el ID no existe, la inserción falla.
  • Fechas: NOW() devuelve fecha y hora actuales; CURDATE() solo la fecha.
Analogía cotidiana: insertar es completar un formulario en papel. Los campos con asterisco (NOT NULL) no se pueden dejar en blanco; el número de trámite lo pone la ventanilla, no vos (AUTO_INCREMENT); y si ponés el DNI de una persona que no está en el padrón, el trámite te lo rebotan (clave foránea).

03

Actualización de Datos (UPDATE)

Los precios suben y el stock se mueve

M

Martín dice:

"Otra vez subió todo. Necesito aumentar un 10% los precios de los repuestos, pero después me di cuenta de que en realidad el aumento fuerte vino solo en los módulos de pantalla, así que quiero poder hacerlo selectivo. Ah, y el cliente 1 está mal cargado: se llama Juan Carlos, no Juan."

Sustento Teórico: la sentencia UPDATE

  • Estructura: UPDATE tabla SET columna = valor WHERE condición;
  • El SET puede leer la propia columna: SET precio = precio * 1.10 es válido, porque el motor lee el valor viejo y escribe el nuevo en un solo paso.
  • Sin WHERE, el UPDATE alcanza a TODAS las filas. A veces eso es exactamente lo que queremos (un aumento general), pero tiene que ser una decisión consciente, no un olvido.
  • LIKE y sus comodines: % representa cualquier cantidad de caracteres (incluso ninguno) y _ exactamente uno. Entonces LIKE '%Módulo%' significa "que contenga la palabra Módulo en cualquier posición".
  • MySQL informa siempre cuántas filas tocó: Rows matched: X Changed: Y. Leer ese número es la forma de confirmar que apuntamos bien.
Analogía cotidiana: es "Buscar y reemplazar" en un procesador de texto. El WHERE es lo que escribís en "Buscar", el SET es lo que escribís en "Reemplazar con", y el botón "Reemplazar todo" sin haber buscado nada primero es exactamente el UPDATE sin WHERE.
⚠️ Regla de oro: escribí primero la consulta como SELECT * FROM tabla WHERE ..., verificá que las filas que ves son las que querés modificar, y recién ahí reemplazá el SELECT * por UPDATE ... SET .... Nunca al revés.

Borrado de Datos (DELETE)

… y restricciones de integridad referencial

M

Martín dice:

"Che, la marca LG la cargué por las dudas pero al final no vamos a trabajarla, sacala. Y ya que estamos, hay un cliente que me pidió que lo borre del sistema, el número 1. Borralo también."

Sustento Teórico: DELETE e integridad referencial

  • Estructura: DELETE FROM tabla WHERE condición; Fijate que no se nombran columnas: el DELETE borra la fila entera. Para "borrar un dato" de una columna se usa UPDATE ... SET columna = NULL.
  • Integridad referencial: una clave foránea impide que quede una fila "huérfana" apuntando a algo que ya no existe. Si borráramos al cliente 1, sus órdenes de servicio quedarían apuntando a un cliente inexistente.
  • Qué hace el motor: nuestras FK están declaradas ON DELETE NO ACTION, que en MySQL/InnoDB se comporta como RESTRICT: rechaza el borrado y devuelve el error 1451.
  • Otras políticas posibles: ON DELETE CASCADE (borra en cascada los hijos) y ON DELETE SET NULL (deja la referencia en nulo). Son decisiones de diseño, no de consulta.
Analogía cotidiana: no podés dar de baja una obra social si todavía hay pacientes afiliados a ella. Primero se resuelve qué pasa con los afiliados; el sistema no te deja crear pacientes flotando en el vacío.
⚠️ El error del Reto 4.2 es intencional. No lo "arregles" borrando a mano todo lo que cuelga del cliente. La consigna es entender por qué la base se niega, y esa negativa es una función del motor trabajando bien, no una falla.

05

Navegación de Datos (LIMIT y Paginación)

Mostrar los datos de a páginas para no saturar al usuario

M

Martín dice:

"En el celular no me entra la lista entera de repuestos, se hace ilegible. Quiero verla de a poquito, como cuando entrás a una tienda online y tenés los botoncitos de página 1, página 2, página 3 abajo de todo. ¿Se puede hacer eso desde la base?"

Sustento Teórico: LIMIT y OFFSET

  • LIMIT n corta el resultado y devuelve como máximo n filas.
  • OFFSET m descarta las primeras m filas antes de empezar a contar. LIMIT 5 OFFSET 5 significa "saltea 5 y traeme los 5 siguientes".
  • Sintaxis abreviada de MySQL: LIMIT 5, 5 equivale a LIMIT 5 OFFSET 5. Cuidado: acá el primer número es cuántas saltear y el segundo cuántas traer, o sea el orden inverso al de la forma larga.
  • La fórmula de la paginación: OFFSET = (número_de_página − 1) × tamaño_de_página.
  • Sin ORDER BY no hay paginación posible: si el orden no está fijado, el motor puede devolver las filas en cualquier orden, y entonces nada garantiza que la "página 2" no repita filas de la "página 1".
Analogía cotidiana: es el mazo de cartas boca abajo. OFFSET es cuántas cartas descartás de arriba sin mirarlas; LIMIT es cuántas levantás después. Y si antes no ordenaste el mazo, cada vez que repartís sale algo distinto.
