01

Vistas (Views)

Facilitar el acceso a los datos y cuidar la privacidad

M

Martín dice:

"Hola chicos. En el local, cuando viene un cliente, le tomamos los datos y abrimos una orden. El tema es que para ver los datos completos de una orden con su cliente, equipo, marca y problema, mis empleados se vuelven locos buscando en un montón de tablas separadas. Además, no quiero que los recepcionistas anden viendo los totales cobrados o los descuentos, pero sí necesitan ver los datos de contacto y el estado de la reparación. ¿Cómo resolvemos esto?"

El truco de las Vistas: Una vista es como una "tabla virtual". No duplica la información ni ocupa espacio extra; es simplemente una consulta SQL compleja guardada en el servidor con un nombre. Quien la use puede consultarla como si fuera una tabla normal y corriente con un simple SELECT, sin tener que saber hacer uniones raras (JOINs) y viendo solo la información que nosotros permitamos.

Analogía: Es como tener una ventana que da hacia una habitación desordenada. En lugar de entrar a buscar las cosas entre el desorden, simplemente mirás por la ventana que ya te enfoca el objeto que necesitás.

02

Índices (Indexes)

Acelerar el motor de búsqueda de la base de datos

M

Martín dice:

"Chicos, a veces cuando busco a un cliente por apellido para ver si ya vino antes, el sistema tarda un poquito en responder. Ahora tenemos pocos clientes cargados, pero me da miedo que cuando tengamos miles de registros el sistema se ponga lentísimo y la gente tenga que esperar en el local."

El truco de los Índices: Si buscas una palabra en un libro de 500 páginas que no tiene índice, te toca revisar hoja por hoja (en bases de datos esto se llama Full Table Scan o escaneo completo). Pero si el libro tiene un índice al final, buscas la letra por la que empieza la palabra, ves el número de página y vas directo. Un índice en SQL hace exactamente eso: crea un atajo ordenado para que el motor vaya directo al dato sin leer toda la tabla.

Analogía: Es como ordenar alfabéticamente un tarjetero físico. Si no estuviera ordenado, tendrías que revisar tarjeta por tarjeta hasta dar con el cliente. Si está ordenado, vas directo a la letra correspondiente.

03

Procedimientos Almacenados (Stored Procedures)

Encapsular procesos repetitivos y evitar errores humanos

M

Martín dice:

"Muchachos, por la inflación, los precios de los repuestos suben todas las semanas. Para cambiarlos, mis empleados tienen que escribir una consulta UPDATE a mano. El otro día, un chico se olvidó de poner la parte del WHERE y casi me cambia el precio de TODOS los repuestos del local al mismo precio. ¡Casi me muero del susto! ¿No podemos automatizar este cambio para que solo pongan el código del repuesto y el precio nuevo sin riesgos?"

El truco de los Procedimientos: Un procedimiento almacenado es una consulta o grupo de consultas SQL que guardamos bajo un nombre único en el servidor. En lugar de escribir el código desde cero y arriesgarnos a cometer errores fatales (como olvidarse de un WHERE), los empleados simplemente llaman al procedimiento usando CALL nombre_procedimiento(datos).

Analogía: Es como programar un botón de marcado rápido en el teléfono. En lugar de marcar los 10 dígitos del número del cliente uno por uno cada vez, tocás el botón "Llamar a Martín" y el teléfono hace todo el proceso de marcado por vos.
  • Reto 3.1

    Crear un procedimiento de actualización segura

    Crea un procedimiento almacenado llamado cambiar_precio_repuesto que reciba dos parámetros: el ID del repuesto y su nuevo precio unitario. Dentro del procedimiento, debe ejecutarse un UPDATE que modifique el precio únicamente del repuesto con ese ID.

    💡 Ayuda para la consola de MySQL

    Como el procedimiento tiene varias líneas de código, recuerda usar el cambiador de delimitadores para que la consola no se confunda:

    DELIMITER //
CREATE PROCEDURE ...
BEGIN
    -- Tu código UPDATE aquí
END //
DELIMITER ;

04

Triggers (Disparadores)

Las alarmas y automatizaciones automáticas de la base de datos

M

Martín dice:

"Gente, les cuento otro dolor de cabeza. A veces un técnico comete un error al registrar una reparación y pone que el stock de un repuesto quede en negativo (por ejemplo, -2 pantallas en el depósito). ¡Físicamente eso es imposible! O tengo repuestos o no tengo. Necesito que la base de datos impida guardar un stock menor a cero automáticamente."

El truco de los Triggers: Un Trigger (o disparador) es un bloque de código SQL que se ejecuta automáticamente cuando ocurre un evento en una tabla específica (al hacer un INSERT, UPDATE o DELETE). Nadie lo llama con CALL; el propio motor SQL lo dispara solo. Lo usamos mucho para revisar que los datos tengan sentido físico antes de que se guarden en el disco rígido.

Analogía: Es como un sensor de movimiento en un pasillo. No necesitas presionar un interruptor para encender la luz; el sensor detecta que pasaste y enciende la bombilla por su cuenta.
  • Reto 4.1

    Crear un Trigger anticaídas de stock

    Crea un trigger llamado trg_control_stock_negativo que se active BEFORE UPDATE (antes de que se actualicen los datos) en la tabla repuesto. Si el stock nuevo (que en triggers se lee con NEW.stock) es menor a 0, debe interrumpir la consulta y arrojar un mensaje de error personalizado.

    💡 Ayuda para interrumpir la consulta en MySQL

    Puedes usar la siguiente sentencia especial para frenar todo y tirar un error en pantalla:

    SIGNAL SQLSTATE '45000'
SET MESSAGE_TEXT = '¡Tu mensaje de error personalizado aquí!';
